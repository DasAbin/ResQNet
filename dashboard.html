HOW THIS SOLVES IT

When floods cut links, phones cannot reach the camp directly. ResQNet stores each message, carries it on any device that moves, and forwards it when a link returns — store, carry, forward. It targets delayed field reports and supply coordination, not urgent rescue: if help is close enough to hear you, shouting beats any protocol, and real offline device-to-device chat already exists elsewhere. An online model scores each possible next hop from observed successes, so queued traffic picks the relay most likely to get through. The same custody protocol also runs between separate OS processes over TCP (node.py, tested on loopback); this map shows the simulator, not field radios.
